# Focus Sessions - Project Instructions

## Project Overview
Build a simple Flutter Focus Sessions app for Android.

## Tech Stack
- Flutter and Dart
- Provider for state management
- SharedPreferences for local persistence
- HTTP for the daily quote API
- Flutter Test for testing

## Project Structure
- lib/models: Data models
- lib/providers: Shared application state
- lib/screens: App screens
- lib/services: API and local storage services
- lib/widgets: Reusable UI widgets
- lib/legacy: Legacy code and bug fixes
- test: Unit and widget tests
- docs: Prompt log and reflection

## Naming Conventions
- Use snake_case for file names.
- Use PascalCase for class names.
- Use camelCase for variables and methods.

## Coding Rules
- Keep business logic outside UI widgets.
- Use Provider consistently for shared state.
- Do not use setState for shared application state.
- Do not add new packages without asking first.
- Write tests for important business logic.
- Keep implementations simple and beginner-friendly.
- Explain code changes and important decisions.
- Do not modify unrelated files.
- Work on one feature at a time.
- Ask before making major architecture changes.
